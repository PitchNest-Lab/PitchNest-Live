# PitchNest: Mode Categorization + Pitch Again (AI memory) + Deck Check

## Context

Three gaps identified against the product roadmap and user requests:

1. **Sessions aren't categorized.** Mode (`panel`/`coach`/`solo`) is never stored as a real column — it only sometimes rides inside the `evaluation_report` JSON. The archive shows coach as "Practice Coach" and lumps panel + solo together as "VC Panel" (`MyPitchesArchive.tsx:417-420`).
2. **No way to re-pitch with AI memory.** A founder who pitched "HealthMate" poorly can't come back and have the panel remember them. The refresh-resume feature (`restSocket.ts:655-668`) proves the transcript-rebuild mechanism works, but only mid-session.
3. **No deck-only audit.** The roadmap's Stage 3 "Health Check Analyzer" pulled forward: upload a deck → AI verdict → downloadable PDF, no live session.

**User decisions (confirmed):** Pitch Again = *new* session with compact memory of the previous attempt (not continuing the old conversation). Deck audit = *standalone* sidebar menu item named **"Deck Check"**.

**Step 0 of implementation:** copy this plan into the repo as `docs/IMPLEMENTATION_PLAN.md` (user requested a plan artifact in the project).

**Build order: A → B → C.** A is small; B depends on A's schema change and touches the same files; C is fully independent.

---

## One-time Supabase SQL (run in dashboard BEFORE deploying backend)

The WS `end_session` insert references new columns — if they don't exist the insert throws and **sessions silently stop saving** (only a console.error at `restSocket.ts:~1065`). Run first:

```sql
-- Feature A
ALTER TABLE sessions ADD COLUMN IF NOT EXISTS mode text;

-- Feature B (verify sessions.id type — bigint vs int — in dashboard)
ALTER TABLE sessions ADD COLUMN IF NOT EXISTS parent_session_id bigint
  REFERENCES sessions(id) ON DELETE SET NULL;
ALTER TABLE sessions ADD COLUMN IF NOT EXISTS pitch_config jsonb;

-- Feature C (match decks.id / users.id types)
CREATE TABLE IF NOT EXISTS deck_audits (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  deck_id bigint REFERENCES decks(id) ON DELETE CASCADE,
  user_id bigint REFERENCES users(id) ON DELETE CASCADE,  -- users.id is numeric in this schema
  report jsonb NOT NULL,
  created_at timestamptz DEFAULT now()
);
CREATE INDEX IF NOT EXISTS deck_audits_deck_idx ON deck_audits (deck_id, created_at DESC);

-- Optional best-effort backfill (some evaluation_report rows may be text/corrupted — skip failures)
UPDATE sessions SET mode = COALESCE(evaluation_report->>'mode', 'panel') WHERE mode IS NULL;
```

## Risks
- **Deploy ordering (highest):** run SQL before backend deploy or session inserts fail silently. Consider defensive catch-and-retry-without-new-columns during rollout.
- **`evaluation_report` inconsistency:** some rows are text/corrupted (`safeParseJSON` exists for this) — backfill is best-effort; frontend fallback covers it.
- **Old rows lack `pitch_config`:** Pitch Again prefills only name+mode there; banner shouldn't promise more.
- **WS trust boundary:** client can forge `previousSession`/`parentSessionId` — ownership check + size clamps in B1 are mandatory.
- **Deck text:** huge or empty (image-only) decks — truncate ~12k chars + reject empty with friendly 400.
- **LLM JSON:** reuse `parseJsonLoose`; `validateDeckAudit` so malformed output never 500s.
- **Rate-limit store:** in-memory, per-instance, resets on restart — fine for current single-instance Render deploy.
